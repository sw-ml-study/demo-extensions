Added extensions/digest, a native streaming SHA-256 primitive: _digest:sha256_bytes for in-memory data and _digest:sha256_file for streaming an existing confined file in bounded chunks, with the u:digest_* MLPL facade. Inserted ahead of the tokenizer work because step 002 shipped checksum verification that no consumer could use: SHA-256 is 64 rounds of 32-bit modular arithmetic per 64-byte block (about 18.6 million blocks for the 1.19 GB artifact downstream pins) and MLPL has no 32-bit integer type, so computing a digest there is impractical rather than merely slow. Confinement matches the sqlite/download surfaces including symlink escape rejection after canonicalization; chunk_bytes bounds resident memory. Satisfied the single-implementation requirement with a shared Sha256Stream type that the bounded download drives from its own read loop, keeping transfer policy (byte limit, tee to temp file) in the download and hashing in the digest crate; http-client keeps sha2 only as a dev-dependency. Tests: NIST one-block and two-block vectors, the empty vector, in-memory versus streamed agreement at chunk sizes 1/64/4096/1MiB over a 4097-byte input, empty file, symlink escape, every fail-closed input, and dynamic/static provider parity; plus an mlplunit record-shape test. Filed request D1 in the new docs/reasoning-from-scratch-requests.md: that repository verifies downloads by byte size alone, which detects truncation but not substitution, and can now pin real digests obtained from the Hugging Face LFS pointer without transferring 1.19 GB; obtaining them is its decision and no sibling repo was modified.
