Implemented pure byte-level BPE encoding and decoding in extensions/hftok: added-token isolation (longest match first), pre-tokenization with the file's own pattern via fancy-regex, the GPT-2 byte-to-unicode alphabet, rank-ordered merging, and the inverse decode keeping control tokens visible. No chat roles, prompts, or model semantics in the module. Caught and fixed a silent-corruption bug during review before committing: the first pre-tokenizer swallowed a mid-scan regex failure and returned the fragments matched so far, which would have encoded a truncated prefix and returned plausible but wrong ids with no error; it now fails with a reason both on run-time pattern failure and when matches do not cover the input, proven by a letters-only-pattern test showing 'the 9' is refused rather than encoded as 'the'. Also removed the panic paths clippy flagged by rebuilding the byte alphabet over u8 with infallible conversions rather than documenting a Panics section. fancy-regex was required because the real pre-tokenization pattern uses a negative lookahead the regex crate cannot compile; it is pure Rust so no C onig build, the use is internal, and no general-purpose regex primitive is exposed since the downstream work order lists regex as not requested. 23 crate tests pass covering every published expectation both directions, merge ranking versus left-to-right, control-token behaviour, 200 deterministic pseudo-random round trips plus punctuation/digit/newline/whitespace cases, non-ASCII bytes, and five error paths. Documented the four-stage algorithm and six limits in docs/hftok-extension.md. The Rust encoder agrees with the Python reference that derived the expected encodings, which is a cross-language check but not independent confirmation since both are mine; step 007 settles it. Full gate passed with PASS pre-commit.
